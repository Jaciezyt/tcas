# TCAS 第一版：实现文档

状态：实现方案，2026-11-23
对应设计：[../design.md](../design.md)。第一版只实现其中的租约这一层，范围比 design.md 第 11 节的阶段 1 小得多。

## 1. 第一版是什么

用户照常自己启动 harness 会话（先 Claude Code，再 AGY、Codex）。这些会话在同一个 workspace（一个检出、装着几个仓库的一个目录，或者几个不在一起的目录）里并行改代码时，TCAS 保证同一个文件同一时刻只有一个会话能改，被挡住的会话立刻知道是谁占着，并且可以在后台等。

只有两个程序：

| 名称 | 是什么 |
|---|---|
| `tcas` | 命令行。用户用它开 workspace、看状态、干预；agent 用它申请和释放租约；harness 的 hook 也调用它（`tcas hook`） |
| `tcasd` | 本机 daemon。保存 workspace、会话、租约和事件日志，所有判定都在这里做 |

接入 harness 靠一个 plugin，里面只有三样东西：hook 配置、一个转发到 `tcas` 的脚本、一份给 agent 看的用法说明。

## 3. 架构

```
 用户终端              harness 会话 A              harness 会话 B
   │ tcas …              │ plugin 的 hook            │ plugin 的 hook
   │                     │ tcas hook … / tcas lease …│
   └──────────┬──────────┴─────────────┬─────────────┘
              │   Unix 套接字 ~/.tcas/tcasd.sock
        ┌─────▼────────────────────────────────────┐
        │ tcasd：workspace · 会话 · 租约 · 事件日志  │  ~/.tcas/tcas.db
        └─────┬────────────────────────────────────┘
              │ git status、stat（只读，不改工作目录）
        workspace 里的检出，一个或多个（用户和所有会话共用）
```

- tcasd 是 design.md 里控制面和 daemon 的合并，只在本机。
- tcasd 不启动会话，不改工作目录里的文件，不调用任何模型。
- 拦截的路径：编辑工具在调用前由 harness 的 hook 问 tcasd；Bash 写文件拦不住，靠命令护栏、装在各仓库里的 git 钩子和调用后的对账。

## 4. 和完整设计的差别

| | design.md | 第一版 |
|---|---|---|
| 租约的持有者 | 任务 | 会话（子 agent 算在父会话里） |
| 租约从哪来 | 方案里的影响面，批准时发放 | 会话第一次改某个文件时自动取得；做较大的改动前用 `tcas lease acquire` 按目录或文件事先申请（建议，不强制） |
| 租约何时释放 | 任务落地 | 持有者提交、主动释放；文件干净，且持有者一段时间没用到它、或者提交过它并结束了这一轮时，让给来申请的会话；会话结束且文件干净 |
| 被占用时 | 调度器加顺序边，排队 | 立即拒绝并告知持有者；会话可以用 `tcas lease wait` 在后台等，没有预约和顺序 |
| 持有租约时等待 | 不允许，所以不会死锁 | 允许，tcasd 检查死锁并结束其中一个等待 |
| 越界的 Bash 写入 | 沙箱事前阻止，或对账后还原 | 只对账和通知，不还原 |
| 会话 | daemon 启动 | 用户启动 |
| 多个仓库 | project 声明仓库，路径写成 `仓库:路径` | workspace 是一个或几个目录，里面的仓库自动发现。路径相对所在的目录，有几个目录时前面带目录名 |

没变的规则：读不受限；申请失败立即返回；不在任何租约内的改动只上报、不还原（这份检出用户自己也在用）；被 git 排除的路径不管。

第一版的数据（事先申请的路径和实际改动的路径差多少、哪些文件争用最多）就是 design.md 第 11 节阶段 0 要测的东西，见 [plan.md](plan.md) 的里程碑 5。

## 6. 实现上的选择

下面这些选择换一个选项都只影响局部，备选列在最后一列。

| 选择 | 定为 | 理由 | 另一个选项 |
|---|---|---|---|
| 实现语言 | Rust | hook 每次工具调用都要起一个进程。本机实测进程启动：`node -e 0` 约 71 ms，`git --version` 约 7 ms，`/bin/sh -c true` 约 4 ms，所以要用编译成原生程序的语言 | Go 同样可行，只影响 [plan.md](plan.md) 第 1、2 节 |
| 默认模式 | `auto`：改文件时自动取得租约 | 不要求 agent 改变做法，也不多花工具调用，互斥照样成立 | `strict`：必须先申请才能改。是一个配置项 |
| 自动取得的租约 | 文件没有未提交改动时让出（提交后，或根本没改成） | 文件回到已提交的状态，别人可以接着改 | 一直持有到会话结束 |
| 被拒之后 | 拒绝理由里给出 `tcas lease wait` 命令。它不在会话的主线程上等：用 harness 的异步机制运行（Claude Code 的后台 shell），等到时会话收到通知或被唤醒；在前台运行会被 hook 改成后台 | 被拒的会话不用自己轮询，等待期间可以继续做别的 | 不提供等待，只能做别的或告诉用户 |
| 等来的租约 | 授予后保留 10 分钟，之后文件没被改就可以让出 | 异步等待下，等到的会话可能没被唤醒或没回来用 | 一直持有到提交或会话结束 |
| 目录租约 | 只表示范围；在它下面改的文件另记文件租约 | 目录租约放掉后，改到一半的文件仍被保护，目录的其余部分别人可以用；`tcas commit` 也知道该提交哪些文件 | 目录租约负责它下面的一切，有文件没提交就整个不放 |
| 先申请再动手 | 建议：会话开始时说明，没申请就改到第三个文件时提醒一次 | 不打断小改动；大的改动在动手前暴露冲突，脚本的写入也事先被占住 | 强制，即 `strict` 模式 |
| 目录的大小 | 目录下被跟踪的文件超过 200 个时拒绝 | 防止一个会话占住一大片 | 不限制 |
| brief | 申请租约时可以带一句话说明要做什么（`--brief`），显示在别的会话看到的各处：会话开始时、被拒时、读到别人的文件时、有人申请了一片范围时。不强制 | 被拒的会话知道对方在做什么，才能决定是等、换个做法还是告诉用户；实测它能认出对方在做同一件事 | 不提供；或者强制必须写 |
| 没写 brief 时 | 别的会话只看到持有的范围，不拿用户发给那个会话的消息来代替 | 用户和一个会话的对话不该自动转给别的会话 | 用会话的第一条用户消息代替 |
| 事先申请的租约 | 文件干净、持有者超过 30 分钟没用到它时，别人一申请就让出。持有者提交过它、这一轮已经结束时，别人一申请也让出，持有者在下一轮开始之前被告知；这一轮还在进行时保留 | agent 忘了释放，或者会话开着没人管，不该一直占着路径；提交过、停下来的会话多半是忘了放 | 一直持有到主动释放或会话结束；或者提交就释放 |
| 有未提交改动的文件 | 租约不过期。持有会话超过 30 分钟没有活动时标为停滞，提示用户转交或强制释放 | 放掉它，别人就会在改到一半的文件上接着改 | 到时间硬性释放 |
| `tcas` 命令的权限 | hook 自动批准 agent 可用的 `tcas` 命令，`tcas commit` 除外 | 否则每次申请和等待都要用户点批准，无人看着时等不了 | 不自动批准，由用户在 harness 的权限设置里放行 |
| 会话结束时还没提交的文件 | 租约保留，别的会话改不了，等用户处理 | 改到一半的文件不该让别人接着改（design.md 第 13.2 节） | 会话结束就全部释放 |
| 多个仓库 | workspace 是一个目录，里面的仓库自动发现，嵌套的检出各算一个仓库 | 和「从父目录启动会话、同时改几个仓库」的用法一致；租约的规则不用改，只有 git 的查询和提交按仓库分 | 每个仓库各开一个 workspace（仍然可以这样用），或者像 design.md 那样逐个声明仓库 |
| 项目的目录不在一起 | 一个 workspace 可以有几个根目录（`tcas workspace add`），规则和 Bash 对账在它们之间是通的。会话改到 workspace 外面的检出时提示一次，不自动加进来 | 会话都从主目录启动，也会去改并排的后端、网站目录；分开成几个 workspace 的话，跨目录的 Bash 改动看不到 | 每个目录各开一个 workspace；或者会话一改到外面的仓库就自动加进来 |
| 被 git 排除的路径 | 一律不管：`.gitignore`、`.git/info/exclude`、全局排除文件三种来源都算。已经被跟踪的文件不算；被排除的目录里嵌着的 worktree 不跟着豁免 | 构建产物、依赖目录、缓存不该要租约；Claude Code 自己建的 worktree 就在常被排除的 `.claude/` 下 | 只认 `.gitignore`；或者提供开关让被排除的文件也受管理 |
| 豁免的目录 | 系统的临时目录（`/tmp`、`$TMPDIR`）、`~/.tcas`、harness 自己的目录内置豁免；用户可以再加，全局的或某个根里面的。豁免的目录不发租约、不拦截、不提示，也不能打开成 workspace | 脚本和测试常在临时目录里建一次性的仓库，不该被管，也不该每次都提示加进 workspace | 只靠「不在任何 workspace 里」 |
| agent 能做的管理 | 能查看；能打开 workspace（限它所在的检出或当前目录）、往里加检出，都不自动批准；能关闭自己打开的、已经空了的。关闭别人的、改设置、强制释放和转交租约只有用户能做 | 打开只增加保护。关闭和强制操作能被用来绕过别人的租约 | 全部只给用户；或者让指定的会话拥有和用户一样的权限 |
| 怎么认出是会话在运行 `tcas` | 环境变量，加上祖先进程里登记过的会话进程 | 实测清掉环境变量之后，祖先进程里仍然有 harness 进程 | 只看环境变量 |
| worktree | 每个 worktree 算一个独立的检出，规则按检出算。在 workspace 目录里的自动发现；在外面的要用 `tcas workspace add` 加进来 | 主检出和 worktree 里的同名文件是两个文件，不该互相挡；Claude Code 自己建的 worktree 都在仓库里面 | 打开主检出时自动管理它在外面的所有 worktree |
| Bash 写了什么 | 调用前后各拍一次 git 状态快照来比 | 不需要常驻的文件监听，没有事件丢失的问题 | 文件监听（design.md 第 6 节），留到需要进行中快照时再做 |
| 命令护栏 | 有别的会话持有租约时，拒绝 `git add -A`、`git stash`、切分支这类影响整个工作目录的命令。先解析 `cd`、`bash -c`、别名等写法；认出是 git 但看不出要做什么的，拒绝 | 共用检出里这是最常见的互相破坏方式 | 不拦，只靠对账事后发现 |
| git 钩子 | 打开 workspace 时装进每个仓库：提交里有别人持有的文件、有别人在工作时变基或 stash，由 git 自己拒绝；提交后自动释放租约。用户的提交也受检查，可以用 `TCAS_ALLOW=1` 放行 | 不看命令怎么写，脚本里的、别名的、用户敲的都管得到；提交在 tcas 之外发生时租约也能及时释放 | 不装，只靠命令护栏和对账 |
| `tcas commit` | 提供，只提交本会话改过的文件 | 暂存区是共用的，普通的 `git commit` 会把别的会话已暂存的文件一起提交 | 不提供，在说明里教 agent 用 `git commit -- <路径>` |
